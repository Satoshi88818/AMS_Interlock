This document — replaces the per-call-site fix from #4 with a structural one, and proves the replacement is actually more robust, not just equally robust

1. The Problem With the Previous Fix

Document #4 found two bugs, both the same shape: a state-changing call (tolerance-exceeded, then separately a heartbeat-driven reconnect) didn't immediately revoke a still-valid-but-stale gate permit, leaving the physical gate open slightly longer than the logical state said it should be. Both were fixed the same way — by adding an explicit "re-sync the permit" call right after the state-changing call, at that specific call site in run_simulation().

That fix works, but it has a structural flaw: it depends on every caller remembering to add a resync call every time a new state-changing path is introduced. That's exactly the discipline that failed twice already, in two different places, during the same short exercise. A fix that requires perfect call-site discipline to hold isn't really fixed — it's patched twice, with unknown odds on the third occurrence.

2. The Refactor

Every state change in InterlockStateMachine already funnels through exactly one internal method: _transition(). Rather than reacting to state changes from the outside at each call site, the fix moves the reaction inside, to that one funnel point — an on_transition callback that fires synchronously, automatically, after every single transition, regardless of which public method caused it.

def _transition(self, to_state: State, actor: str, reason: str): event = AuditEvent(self._clock(), actor, self.state, to_state, reason) self.state = to_state self.audit_log.append(event) self._log_sink(event) self._on_transition(event) # <-- the choke point 

EdgeNode in the hardware simulator now wires its permit-resync logic to this hook once, at construction, instead of scattering three manual calls across run_simulation(). The three manual call sites were deleted entirely — not left in place as a redundant safety net, because the point of this exercise is to prove the structural fix is sufficient on its own.

3. Proving the Refactor Is a Real Improvement, Not Just a Different-Looking Fix

Three specific pieces of evidence, beyond "the existing tests still pass":

A test that exercises a call site the manual approach never touched. test_choke_point_requires_no_call_site_changes_for_new_transition_paths drives recovery_fail() — a transition (RECOVERY → FAULT) that was never one of the three manually-patched call sites — and confirms the permit is still correctly revoked, with zero new code written for it. This is the direct test of the claim "new transition paths are covered automatically."

A test that exercises a fully internal transition with no external event at all. test_on_transition_hook_fires_for_every_state_change_including_watchdog confirms the hook fires even for the watchdog's internally-triggered fault (tick() calling _transition() with no corresponding public "fault" call from outside) — proving the hook is wired to the state machine's actual transition mechanism, not to any particular set of public methods.

A wider fuzz run that adds a dimension never fuzzed before. The capstone property test now also randomizes manual-stop timing in combination with network conditions, motion excursions, and crashes — a combination not covered in document #4's fuzzing. Under the old approach, adding this dimension would have required checking whether manual-stop's call site had a resync call (it did, by luck of having been one of the original three) — under the new approach, no such check is needed because there's no call-site-specific logic left to check. Ran clean across 1000 examples in the committed test, and separately verified clean across 3000 examples including this dimension during development (see Section 6).

4. Backward Compatibility

The on_transition parameter is optional and defaults to a no-op, so every prior test file (test_interlock_state_machine.py, test_interlock_properties.py, test_clock_synchronization.py) required zero changes and passes unmodified against the refactored InterlockStateMachine.

8. Source: clock_sync.py (unchanged by this refactor — included for completeness, since it's part of the working system)

""" Clock-domain design for the Tier 0 interlock. GOVERNING PRINCIPLE: Every time-based SAFETY decision is made using only the local clock of the actor making that decision. A timestamp or clock reading from another actor is NEVER used as an input to a safety-timing decision. Cross-actor time is used only for audit-log correlation, where its uncertainty is explicitly bounded and reported -- never assumed exact. Why this principle, rather than "synchronize everything": The permit-staleness budget (permit_max_age_us, default 50us) is far tighter than any network-based clock synchronization protocol can reliably guarantee across two independent oscillators. NTP achieves single-digit to tens of milliseconds -- roughly 1000x too coarse. Even hardware-timestamped IEEE 1588 PTP over a real network path typically achieves tens to low hundreds of nanoseconds only under good conditions (hardware timestamping at every hop, stable PTP grandmaster, minimal asymmetry) -- achievable, but fragile, and a silent degradation in sync quality would silently widen the effective safety margin without tripping any explicit fault. Two different solutions are used for the two boundaries in this system, chosen because they have very different requirements: 1. FPGA <-> Edge (needs ~50us-scale agreement): Modeled here as a SHARED hardware counter -- e.g. a free-running counter on the treatment-head backplane, readable by both the FPGA fabric and the edge SoC via a memory-mapped register or a direct low-latency link (not a general network). This is not two clocks kept in sync; it is the SAME physical counter read by both sides, which sidesteps the synchronization problem entirely rather than solving it. Which oscillator and which bus is a hardware decision outside this software model's scope. What this module fixes is the SOFTWARE CONTRACT: gate permits are timestamped and validated purely in this shared tick domain, never in either actor's independent wall-clock domain. If a shared-counter link is not hardware-feasible for a given rack design, the fallback is hardware-timestamped PTP over a dedicated point-to-point link (not a switched network) with an explicit, monitored sync-quality metric that itself feeds a fault condition if it degrades -- raised as an open item in Section "Open Items" below, since that fallback is not implemented in this reference model. 2. Edge <-> Cloud (100ms-scale heartbeat, WAN distances): Deliberately NOT synchronized for safety purposes. See interlock_state_machine.py: cloud_heartbeat_missed() and cloud_heartbeat_received() carry NO cloud-supplied timestamp. Whether a heartbeat was "missed" is determined entirely by the edge's own local monotonic clock measuring elapsed time since it expected one to arrive. Plan identity is checked by content hash, not timestamp, for the same reason: hash comparison requires no clock agreement at all. A loosely-synchronized NTP/PTP-over-WAN time is assumed to exist for AUDIT-LOG READABILITY ONLY (so a human reviewing logs from both sides can roughly align them) and is never read by any safety-decision code path. OPEN ITEMS (not resolved by this module -- flagged for hardware/ops review): - Confirm shared-counter hardware feasibility for the actual rack design, or specify the PTP-over-dedicated-link fallback with a monitored sync-quality fault. - Specify the audit-log clock-offset estimation process for edge<->cloud (e.g., periodic NTP/PTP offset samples attached to log segments) so a post-hoc reviewer can bound cross-actor event ordering uncertainty without assuming false precision. - This module assumes the shared counter itself cannot fail silently (e.g., freeze, wrap, or desync at the hardware level) -- that failure mode belongs in the hardware FMEA, not this software FMEA. """ from dataclasses import dataclass from typing import Optional from interlock_state_machine import InterlockStateMachine, gate_may_be_open @dataclass(frozen=True) class GatePermit: """ A permit the edge node issues to the FPGA authorizing it to open the beam gate for one spot/pulse. issued_at_us is in the SHARED FPGA-edge tick domain (microseconds since an arbitrary shared epoch on the shared counter) -- it is deliberately NOT the edge's own wall-clock time, and must never be compared against the edge's own wall clock. """ spot_id: str issued_at_us: int def issue_gate_permit( fsm: InterlockStateMachine, current_shared_ticks_us: int, spot_id: str, ) -> Optional[GatePermit]: """ Issue a gate permit, gated directly on the interlock state machine's own authority model (spec Section 2): a permit is only issuable when the FSM's state allows the gate to be open at all. This ties permit issuance to the FSM's judgment rather than letting a caller issue permits independent of it. """ if not gate_may_be_open(fsm.state): return None return GatePermit(spot_id=spot_id, issued_at_us=current_shared_ticks_us) class FpgaGateValidator: """ Reference model of the FPGA-side permit check. Deliberately the simplest possible logic (per spec Section 5: "the fastest loop should have the least logic") -- a single integer comparison in the shared tick domain. No unit conversion, no clock-skew compensation term exists in this code, because there is no skew to compensate for: both sides read the same counter, by construction. """ def __init__(self, permit_max_age_us: float): self.permit_max_age_us = permit_max_age_us def validate(self, permit: Optional[GatePermit], current_shared_ticks_us: int) -> bool: if permit is None: return False age_us = current_shared_ticks_us - permit.issued_at_us if age_us < 0: # A permit timestamped in the future relative to the shared # counter cannot happen in a genuinely shared clock domain -- # if it does, that indicates a hardware/logic fault upstream, # not a valid permit. Fail closed. return False return age_us <= self.permit_max_age_us

""" Hardware simulation for the Tier 0 interlock. 11. What This Still Does Not Close

Restating from document #4, since none of this refactor addresses these — they remain hardware/process items outside what a software refactor can resolve:

Real FPGA/RTL timing (propagation delays, clock-domain-crossing metastability, register setup/hold times) is not modeled.

The physical feasibility of the shared-counter hardware from the clock synchronization design is assumed, not validated.

UnreliableNetwork's independent-drop model is a simplification of real WAN behavior (no correlated bursts, no variable latency, no reordering).

The four safety-budget constants (hold_timeout_ms, heartbeat_miss_threshold, degraded_max_duration_s, degraded_max_dose_fraction_pct) remain engineering placeholders pending clinical sign-off (FMEA #7 from document #2).

12. Recommended Next Step

At this point, the software-simulatable design work on the Tier 0 interlock has gone through spec → FMEA → property testing → clock-domain design → hardware simulation → structural hardening, with each stage finding and fixing something the previous stage couldn't see. Further simulation work has diminishing returns relative to the remaining open items, all of which require inputs this process cannot generate on its own: clinical sign-off on the four budget constants, a hardware decision on the shared-counter feasibility, and eventually a hardware-in-the-loop test rig to validate the RTL implementation against this software model's transition table as its behavioral specification. Those are the next real steps, and they belong with the people who own those decisions, not with further rounds of simulation.
